# OnlineStore

A Flutter web app for ordering spare parts and booking services, with a clean admin dashboard to manage products and customer requests. Built with Flutter and Firebase (Auth, Firestore, Storage, Hosting).

![Flutter](https://img.shields.io/badge/Flutter-Web-02569B?logo=flutter&logoColor=white)
![Firebase](https://img.shields.io/badge/Firebase-Auth%20%7C%20Firestore%20%7C%20Storage%20%7C%20Hosting-FFCA28?logo=firebase&logoColor=black)

## Features

**Customers**
- Sign up and log in with email and password
- Browse and search spare parts with photos, price and stock
- Cart and checkout with name, phone and delivery address
- Book a service (repair, installation, maintenance, inspection) with a preferred date
- Track every order and service request with live status updates

**Admin**
- Dashboard with new requests, in-progress, completed, product count and low-stock alerts
- Live in-app alert and badge when a new order or service request arrives
- Optional email notification to all admins (readable on mobile)
- Orders list with filters by status and type, one-tap call and email to the customer
- Update request status: New, Contacted, In progress, Completed, Cancelled
- Add, edit and delete products with image upload, description, price and quantity

## Tech stack

| Layer | Technology |
|---|---|
| UI | Flutter (Material 3), web |

## Getting started

### Prerequisites
- Flutter SDK (stable) with web enabled: `flutter config --enable-web`
- Node.js 20+ and the Firebase CLI: `npm i -g firebase-tools`
- FlutterFire CLI: `dart pub global activate flutterfire_cli`

### 1. Clone and prepare

```bash
git clone https://github.com/Siddiqui145/OnlineStore.git
cd OnlineStore
flutter create . --platforms web --project-name partshub
flutter pub get
```

### 2. Set up Firebase
1. Create a project at the [Firebase console](https://console.firebase.google.com).
2. Enable **Authentication → Email/Password**.
3. Create a **Firestore** database and a **Storage** bucket (production mode).
4. Connect the app:

```bash
firebase login
flutterfire configure      # choose your project and the web platform
```

### 3. Deploy security rules

```bash
firebase use --add
firebase deploy --only firestore:rules,firestore:indexes,storage
```

If asked to let Storage read Firestore (used to check the admin role), answer yes.

### 4. Create the first admin
1. Run the app and sign up with your admin email.
2. In the Firebase console open **Firestore → users → your document** and change `role` from `customer` to `admin`.
3. Sign out and sign in again to see the admin dashboard.

Users cannot change their own role; the security rules only allow this from the console.

### 5. Run locally

```bash
flutter run -d chrome
```

### 6. Deploy to Firebase Hosting

```bash
flutter build web --release
firebase deploy --only hosting
```

The app is live at `https://<your-project-id>.web.app`.

If product images do not appear on the hosted site, apply the included CORS file:

```bash
gcloud storage buckets update gs://<your-bucket> --cors-file=cors.json
```

## Admin email notifications (optional)

New requests always appear instantly in the dashboard. To also receive an email:

1. Upgrade the Firebase project to the **Blaze** plan (required for Functions and Extensions).
2. Install the **Trigger Email from Firestore** extension with collection name `mail` and your SMTP provider.
3. Deploy the function:

```bash
cd functions && npm install && cd ..
firebase deploy --only functions
```

The function in `functions/index.js` emails every user with `role == "admin"` whenever an order or service request is created.

## Data model

| Collection | Fields |
|---|---|
| `users/{uid}` | name, phone, email, role (`customer` or `admin`) |
| `products/{id}` | name, category, description, price, quantity, imageUrl, createdAt |
| `orders/{id}` | type (`spare_part` or `service`), userId, customerName, phone, email, address, items, total, serviceType, preferredDate, notes, status, createdAt, updatedAt |

Storage path: `products/*` (images only, max 5 MB, admin write).

## Security

- Customers can only read their own profile and orders.
- Only admins can create, edit or delete products and update order status.
- Roles cannot be self-assigned.
- Image uploads are restricted to admins, image types and 5 MB.
